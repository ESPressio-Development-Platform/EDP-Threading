# Optional current-context binding

[Normative contract and setup sequence](../docs/CONTEXT-BINDING.MD). [Public/integration reference](Reference-threading-ContextBinding). [Entry guard reference](Reference-threading-detail-ContextBindingScope).

This is domain-neutral Threading owner integration. Application Bootstrap selects exactly one qualified typed carrier, provides fixed immutable direct-slot records/unique identities, and retains every borrowed object through native and downstream capture/export retirement. Ordinary unselected builds instantiate the original router and no carrier/TLS/setup words. Selected startup fails closed under one finite Clock budget; a separate explicit budget continues retained cleanup. No capture gateway or archive is implemented here.

Native entry/retirement and lower infrastructure must remain excluded from future AST method instrumentation. Eligible inner work begins only inside the successfully bound persistent body. Core migration/activation does not assign another identity. One packed fact byte records the coupled but distinct binding phase, native ownership and exceptional-exit fact; no quiescence or durability claim follows from registration alone.

## Native failure acceptance project

The maintained [SDK acceptance fixture](../tests/context-binding-hil/README.MD) uses actual Threading ownership and native TLS/execution over explicit fault-forwarding test adapters. It exercises foreign binding preservation, UnsupportedContext, partial native startup, bounded late acknowledgement, repeated fixed-backing incarnations and retained retirement mismatch on both boards/frameworks. The terminal failed owner remains live until reset. These are owner-lifetime checks, not capture or durable-export acceptance.
